    سيكون لتطبيق الويب [personne1] البنية التالية:

    هذه البنية هي بنية أحادية الطبقة: لا توجد طبقات [métier] أو [dao]، بل طبقة واحدة فقط هي [web]. [ServletPersonne] هو وحدة التحكم في التطبيق التي تعالج جميع طلبات العملاء. وللرد على هذه الطلبات، تستخدم إحدى العروض الثلاثة [formulaire, réponse, erreurs].

    سيكون ملف web.xml الخاص بالتطبيق /personne1 كما يلي:

    
<?xml version="1.0" encoding="UTF-8"?>
<web-app id="WebApp_ID" version="2.4"
    xmlns="http://java.sun.com/xml/ns/j2ee"

    xsi:schemaLocation="http://java.sun.com/xml/ns/j2ee http://java.sun.com/xml/ns/j2ee/web-app_2_4.xsd">
    
  <display-name>mvc-personne-01</display-name>
    <!--  ServletPersonne -->
    <servlet>
        <servlet-name>personne</servlet-name>
        <servlet-class>
            istia.st.servlets.personne.ServletPersonne
        </servlet-class>
        <init-param>
            <param-name>urlReponse</param-name>
            <param-value>
                /WEB-INF/vues/reponse.jsp
            </param-value>
        </init-param>
        <init-param>
            <param-name>urlErreurs</param-name>
            <param-value>
                /WEB-INF/vues/erreurs.jsp
            </param-value>
        </init-param>
        <init-param>
            <param-name>urlFormulaire</param-name>
            <param-value>
                /WEB-INF/vues/formulaire.jsp
            </param-value>
        </init-param>
    </servlet>
    <!--  تعيين ServletPersonne-->
    <servlet-mapping>
        <servlet-name>personne</servlet-name>
        <url-pattern>/main</url-pattern>
    </servlet-mapping>
    <!--  ملفات الصفحة الرئيسية -->
    <welcome-file-list>
        <welcome-file>index.jsp</welcome-file>
    </welcome-file-list>
</web-app>

    ماذا يقول ملف التكوين هذا؟

    • الأسطر 34-37: يتم معالجة URL /main بواسطة السيرفلت المسمى personne
    • الأسطر 10-13: السيرفلت المسمى personne هو مثيل لفئة [ServletPersonne]
    • الأسطر 14-19: تحدد معلمة تكوين تسمى [urlReponse]. وهي عنوان URL للطريقة [réponse].
    • الأسطر 20-25: تحدد معلمة تكوين باسم [urlErreurs]. هذا هو عنوان URL للطريقة [erreurs].
    • الأسطر 26-31: تحدد معلمة تكوين باسم [urlFormulaire]. هذا هو عنوان URL للطريقة [formulaire].
    • السطر 40: ستكون [index.jsp] هي الصفحة الرئيسية للتطبيق.

    تخضع عناوين URL للصفحات JSP الخاصة بعروض [formulaire, réponse, erreurs] لمعلمة تكوين لكل منها. وهذا يسمح بنقلها دون الحاجة إلى إعادة تجميع التطبيق.

    • الأسطر 18-38: ستقوم الصفحة JSP بإنشاء نموذج HTML (علامة <form>)
    • السطر 18: لا تحتوي العلامة <form> على سمة action لتعيين عنوان URL الذي سيتولى معالجة القيم المرسلة بواسطة الزر [Envoyer] من النوع submit (السطر 32). سيتم عندئذٍ إرسال قيم النموذج إلى عنوان URL الذي تم الحصول على النموذج منه، أي عنوان URL لوحدة التحكم [ServletPersonne]. وبالتالي، يتم استخدام هذا العنصر في الوقت نفسه لإنشاء النموذج الفارغ المطلوب مسبقًا بواسطة GET ومعالجة البيانات المدخلة التي سيتم إرسالها إليه باستخدام الزر [Envoyer].
    • القيم المرسلة هي قيم الحقول HTML و [txtNom] (السطر 22) و [txtAge] (السطر 26) و [action] (السطر 37). سيسمح هذا المعامل الأخير للمراقب بمعرفة ما يجب عليه فعله.
    • عند العرض الأولي للنموذج، يتم تهيئة حقول الإدخال [txtNom, txtAge] على التوالي باستخدام المتغيرات [nom] (السطر 22) و [age] (السطر 26). تحصل هذه المتغيرات على قيم سماتها من الاستعلام (السطران 6-7)، وهي سمات نعلم أنها تم تهيئتها بواسطة السيرفلت. وبالتالي، فإن السيرفلت هو الذي يحدد المحتوى الأولي لحقول الإدخال في النموذج.
    • السطر 33: يتيح الزر [Rétablir] من النوع [reset] إعادة النموذج إلى الحالة التي كان عليها عندما استلمه المتصفح.
    • السطر 34: الزر [Effacer] من النوع [reset] ليس له أي وظيفة في الوقت الحالي.

    بعد ذلك، سنطلق على هذه العرض اسم العرض [formulaire(nom, age)] عندما نرغب في تحديد اسم العرض ونموذجه في آن واحد. من ناحية أخرى، تذكر أنه عندما ينقر المستخدم على الزر [Envoyer]، يتم إرسال المعلمات [txtNom, txtAge] إلى عنوان URL [/personne1/main].

    5.7.2. تهيئة وحدة التحكم

    عندما يتم تحميل فئة وحدة التحكم بواسطة حاوية السيرفلت، يتم تنفيذ طريقتها [init]. وستكون هذه المرة الوحيدة. وبمجرد تحميلها في الذاكرة، ستبقى وحدة التحكم فيها وستعالج طلبات العملاء المختلفين. يخضع كل عميل لخيط تنفيذ، وبالتالي يتم تنفيذ طرق وحدة التحكم في وقت واحد بواسطة خيوط مختلفة. تجدر الإشارة إلى أنه، لهذا السبب، يجب ألا يحتوي وحدة التحكم على حقول يمكن أن تقوم طرقها بتعديلها. يجب أن تكون حقولها للقراءة فقط. يتم تهيئتها بواسطة الطريقة [init] التي تتمثل مهمتها الرئيسية في ذلك. تتميز هذه الطريقة في الواقع بأنها تُنفذ مرة واحدة فقط بواسطة مؤشر ترابط واحد. وبالتالي، لا توجد مشاكل تتعلق بالوصول المتزامن إلى حقول وحدة التحكم في هذه الطريقة. تهدف الطريقة [init] إلى تهيئة الكائنات الضرورية لتطبيق الويب والتي سيتم مشاركتها للقراءة فقط من قبل جميع خيوط العملاء. يمكن وضع هذه الكائنات المشتركة في مكانين:

    public void doGet(HttpServletRequest request, HttpServletResponse response)
            throws IOException, ServletException {

        // نتحقق من كيفية إجراء تهيئة السيرفلت
        if (erreursInitialisation.size() != 0) {

        String méthode=request.getMethod().toLowerCase();
        // يتم استرداد الإجراء المطلوب تنفيذه
        String action=request.getParameter("action");
        // الإجراء؟
        if(action==null){
            action="init";
        }
        // تنفيذ الإجراء
        if(méthode.equals("get") && action.equals("init")){
            // بدء تشغيل التطبيق

            return;

            // التحقق من صحة نموذج الإدخال
            doValidationFormulaire(request,response);
            return;
        }
        // حالات أخرى
        doInit(request,response);
    }

    • السطور 19-26: يتم التحقق من صحة هذين المعلمتين
    • الأسطر 28-33: إذا كان أحد المعلمات خاطئًا، يتم عرض طريقة العرض [erreurs(erreursAppel)]. تذكر نموذج طريقة العرض هذه: 
    
<%
// يتم استرداد بيانات النموذج
  ArrayList erreurs=(ArrayList)request.getAttribute("erreurs");  
%>
    • الأسطر 35-38: إذا كانت المعلمتان "txtNom" و"txtAge" المسترجعتان تحتويان على قيم صالحة، يتم عرض العرض [reponse(nom,age)]. يجب تذكر نموذج العرض [reponse]: 
    
<%
    // يتم استرداد البيانات من النموذج
  String nom=(String)request.getAttribute("nom");
  String age=(String)request.getAttribute("age");
%>
